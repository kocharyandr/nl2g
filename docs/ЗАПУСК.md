# Запуск NL2G из репозитория

Инструкция для macOS (Apple Silicon) и Linux. Проверено на Mac с 51.5 ГБ общей памяти, Python 3.12.

## Что понадобится

| Что | Зачем | Сколько места |
|---|---|---|
| Python 3.12 и [uv](https://docs.astral.sh/uv/) | окружения сервисов | — |
| [Ollama](https://ollama.com) | все LLM-роли | модели ≈ 24 ГБ |
| Redis | состояние сессий оркестратора | — |
| Git | клонировать репозиторий | — |
| Аккаунт Hugging Face с доступом к `black-forest-labs/FLUX.2-klein-9B` | только для правок картинок диффузией | веса ≈ 35 ГБ |

Память: без диффузии хватает 40 ГБ (три LoRA-роли + оркестратор). Диффузия добавляет ≈ 33 ГБ; на одной машине с 48–64 ГБ она работает по очереди с LoRA-ролями — `start_all.sh --diffusion` настраивает это сам.

```bash
# macOS
brew install uv ollama redis git
# Linux (Debian/Ubuntu): uv — curl -LsSf https://astral.sh/uv/install.sh | sh; ollama — curl -fsSL https://ollama.com/install.sh | sh; redis — apt install redis
```

## 1. Клонировать и собрать окружения

```bash
git clone https://github.com/kocharyandr/nl2g.git
cd nl2g

for d in sql_agent chart_agent chart_agent/code_executor chat diffusion_service; do
  (cd $d && uv venv --python 3.12 .venv && uv pip install -r requirements.txt)
done
(cd guardrails_api && uv sync)      # опционально: фильтр безопасности
```

## 2. Конфигурация

```bash
for d in sql_agent chart_agent chat guardrails_api langfuse; do cp $d/.env.example $d/.env; done
```

В `sql_agent/.env` укажите, где лежат базы:

- `DB_PATH` — база по умолчанию; в репозитории есть `sql_agent/demo_data/РозничнаяСеть.sqlite` (русская схема, демо).
- `DATASOURCE_ROOTS` — каталоги с другими SQLite-базами через `:`; необязательно. Для замеров на PAUQ нужен сам датасет PAUQ (`database/<db>/pauq_<db>.sqlite`), он в репозиторий не входит.
- `PROFILES_DIR` — папка с Schema Profile (`<db_id>.json`); для демо-базы профиль лежит рядом с ней.

Остальные `.env` менять не нужно: `start_all.sh` передаёт адреса сервисов переменными окружения.

## 3. Модели

```bash
ollama serve &                                   # если не запущен как служба
bash sql_agent/scripts/install_ollama_models.sh  # qwen2.5-coder:14b + три LoRA-роли из sql_agent/adapters
ollama pull qwen2.5vl:7b                         # судья правок (нужен только для оценки)
```

Диффузия (только если нужны правки картинок):

```bash
cd diffusion_service
HF_TOKEN=<ваш токен> .venv/bin/python download_flux_snapshot.py   # ≈ 35 ГБ, лицензию FLUX.2 нужно принять на Hugging Face
cd ..
```

Guardrails при первом старте сам скачивает GLiNER2 (`fastino/gliner2-multi-v1`).

## 4. Запуск

```bash
bash start_all.sh                  # Redis, Ollama, sql_agent, executor, chart_agent, чат
bash start_all.sh --diffusion      # то же + правки картинок
bash start_all.sh --status         # что отвечает
bash stop_all.sh
```

Чат: http://127.0.0.1:7861. Первый вопрос прогревает модели (≈ 1 мин), дальше график приходит за 50–70 с.

Проверить SQL-агент отдельно:

```bash
cd sql_agent
.venv/bin/python scripts/ask.py --list                           # какие базы видит
.venv/bin/python scripts/ask.py "выручка по городам за год"      # вопрос к базе по умолчанию
```

## 5. Как пользоваться чатом

1. Включите галочку «Данные из базы» и выберите базу в списке.
2. Спросите: «построй график выручки по городам» — придёт график, под ним SQL.
3. Правка текстом до подтверждения меняет код графика: «а теперь линией», «подпиши значения».
4. «Подтвердить» → правка картинки диффузией: «нарисуй нейросетью в стиле акварели». Работает только с `--diffusion`.
5. Новый вопрос к базе после построенного графика — через «Отмена» или новую сессию (обновить страницу): пока видны кнопки подтверждения, любой текст считается правкой.

## 6. Замеры (необязательно)

Скрипты в `sql_agent/scripts/`, результаты прошлых прогонов — в `sql_agent/PAUQ_*`, `sql_agent/МТС_ПРАВКИ/`:

```bash
cd sql_agent
.venv/bin/python scripts/run_pauq.py -n 100 -o pauq_results_100.json   # EX ru/en на PAUQ (нужен датасет)
.venv/bin/python scripts/pauq_stats.py pauq_results_100.json
bash scripts/run_pauq_charts_all.sh                                    # вопрос → график → правка → судья, ≈ 9 ч на Mac
bash scripts/status.sh                                                 # сводка прогресса
```

## Если что-то не так

| Симптом | Причина | Что сделать |
|---|---|---|
| `health` SQL-агента отвечает `degraded` | Ollama не запущен или модели не собраны | `ollama list` должен показывать `nl2sql-schema/sql/critic` |
| Ответ дольше 2 минут | модель выгрузилась из памяти | `OLLAMA_KEEP_ALIVE=30m` (так ставит `start_all.sh` без диффузии) |
| HTTP 503 при правке картинки | FLUX и LoRA-роли вместе не влезли в память | запускать с `--diffusion` (выгружает LoRA-роли) или больше памяти |
| Ошибка `TLS handshake timeout` у `ollama pull` | прокси в окружении | снять `HTTPS_PROXY`/`HTTP_PROXY` перед `ollama serve` |
| «Запрос вернул только текстовые колонки» | вопрос без числовой меры | переформулировать: «сколько…», «сумма…», «топ-10…» |
