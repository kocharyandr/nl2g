## Как получено
1. `scripts/run_mts_edits.py --phase chart` — вопрос по-русски к базе PAUQ → SQL-агент (LoRA, Ollama) → график → «Подтвердить».
2. `scripts/run_mts_edits.py --phase edit` — генеративная правка (FLUX.2 Klein 9B + LoRA, seed 42, одна итерация, автовалидация выключена).
   К промпту добавлен префикс «Нарисуй нейросетью в новом стиле:» — иначе роутер Матвея отправляет цветовые правки в matplotlib, а не в диффузию;
   и приписка из диплома «Сохрани график 1 в 1…».
3. `scripts/judge_edits.py` — судья из диплома Матвея (критерии A1-5/P1-5, Qwen2.5-VL-7b через Ollama, temperature 0), агрегаты A / P / AP.

## Наблюдения
- Уровень 1 (цвет) и большинство уровня 2 проходят по всем критериям; уровень 3 (реализм) ломает данные: «пирог» → яичница (P=0).
- Судья смещён в плюс, как и отмечено в дипломе (κ≈0.6): правка 8 (все яйца одного размера, значения потеряны) получила P3 «пропорции сохранены».
- Правка 7: судья пишет положительные evidence («circles replaced with white eggs») и ставит pass=false по всем A — противоречие модели, не парсера (проверено с ужесточённым парсером).

## Что починено в интеграции по ходу (chart_agent)
- `sql_source_node`: числа, объявленные в Spider/PAUQ как TEXT (`MPG`, `Horsepower`, строки `'null'`), считаются мерой — раньше узел просил «добавить меру» и SQL-агент отвечал `count(*)` (график из одной точки).
- `table_ingest`: такие колонки приводятся к числу.
- `table_node`: круговая диаграмма без колонки категорий отправляется планировщику на повтор (раньше сектора были без подписей).
- `table_code_executor`: подпись берётся из индекса/текстовой колонки, если план не указал x_col.
- `image_generation_validator_agent`: вердикт судьи читается из `pass`/`passed`/`verdict` и строковых `"true"/"false"`.
Тесты: `chart_agent/tests/test_sql_source.py`, `test_code_executor_payload.py` — проходят.
